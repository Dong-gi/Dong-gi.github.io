↓ shell

Static HTTPS 서버 설정

↓ nginx

server { listen 0.0.0.0:443 ssl; listen [::]:443 ssl; server_name g50.4joy.link; ssl_certificate "/.../fullchain.pem"; ssl_certificate_key "/.../privkey.pem"; ssl_session_cache shared:SSL:10m; ssl_session_timeout 1d; ssl_session_tickets off; ssl_protocols TLSv1.2 TLSv1.3; ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384; ssl_prefer_server_ciphers off; location / { root /.../; index index.html; charset utf-8; add_header Cache-Control "no-cache"; } error_page 404 /404.html; error_page 500 502 503 504 /50x.html; location = /50x.html { root /usr/share/nginx/html; } }

TLS 설정에 관하여

  • 위 값은 Mozilla SSL Configuration Generator의 intermediate 프로파일을 따른 것이다. 직접 외우지 말고 그 생성기에서 받아 쓰는 편이 낫다
  • TLS 1.0/1.1은 쓰지 않는다. RFC 8996(2021)이 둘을 폐기했고 주요 브라우저가 이미 막았다
  • RC4는 금지되어 있다. RFC 7465(2015). 3DES(DES-CBC3)도 Sweet32 때문에 빼야 한다
  • ECDHE로 시작하는 스위트를 쓰는 이유는 전방향 보안(forward secrecy)이다. 서버 개인키가 나중에 새더라도 지난 세션을 복호화할 수 없다
  • TLS 1.3의 스위트는 ssl_ciphers로 고르지 않는다. 프로토콜이 정한 셋만 쓰므로 nginx가 알아서 한다
  • ssl_prefer_server_ciphers off인 이유는, 요즘 클라이언트가 자기 하드웨어에 맞는 것(AES-NI가 있으면 AES-GCM, 없으면 ChaCha20)을 더 잘 고르기 때문이다

location 패턴

경로 매치를 위한 여러 패턴을 지원하며, 쿼리 문자열은 당연히 경로 평가에 영향 없다

  • location /abc : /abc로 시작하는 경로에 매치
  • location = /abc : /abc와 일치하는 경로에 매치
  • location ~ \.(gif|jpg|jpeg)$ : 정규식을 포함하는 경로에 매치
  • location ~* \.(gif|jpg|jpeg)$ : 대소문자 구별 없이, 정규식을 포함하는 경로에 매치
  • location ^~ /static/ : 정규식으로 시작하는 경로에 매치

리버스 프록시 설정

↓ nginx

location / { proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header Host $http_host; proxy_set_header X-NginX-Proxy true; proxy_pass https://127.0.0.1:50000/; charset utf-8; }

Basic Auth 설정

↓ shell

$ sudo htpasswd -c /.../.htpasswd username

↓ nginx

location /password { auth_basic "Input Password"; auth_basic_user_file /.../.htpasswd; root /.../; charset utf-8; }
