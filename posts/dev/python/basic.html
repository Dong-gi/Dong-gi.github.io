Formatted string literal(aka. f-string)

  • f_string ::= (literal_char | "{{" | "}}" |replacement_field )*

    • {{, }}는 각각 {, }를 표시하기 위한 리터럴

  • replacement_field ::= "{"f_expression [!conversion] [:format_spec] "}"
  • f_expression : 값을 산출하는 표현식
  • conversion ::= "s" | "r" | "a"

    • 각각 해당하는 함수를 호출한다 : !s → str(), !r → repr(), !a → ascii()

  • f_expression이 산출한 값이 conversion을 거쳐 __format__(format_spec)으로 포매팅된다
  • format_spec ::= [[fill]align][sign][#][0][width][grouping_option][.precision][type]
  • fill ::= 임의_문자
  • align ::= "<" | ">" | "=" | "^"
  • sign ::= "+" | "-" | " "
  • '#' 옵션이 있으면 2, 8, 16진수 앞에 '0b', '0o', '0x'를 각각 붙인다
  • width ::= digit+
  • grouping_option ::= "_" | ","
  • precision ::= digit+
  • type ::= "b" | "c" | "d" | "e" | "E" | "f" | "F" | "g" | "G" | "n" | "o" | "s" | "x" | "X" | "%"

구문

  1. for

    2. for문은 순회 객체에 대하여 iter()를 호출한다. iter()는 __next__() 메서드를 정의한 iterator 객체를 반환하며, __next__()가 전달하는 값을 하나씩 루프에 사용한다

    더 이상 요소가 없을 때 __next__()는 StopIteration 예외를 발생시키고, for 루프는 종료된다. 클래스 자체에 __next__()가 정의되어 있다면, iter()는 self를 반환하는 것으로 충분하다

  2. 콤마로 구분된 값들을 자동으로 튜플로 구성하여 다중 할당, 다중 반환이 가능하다

  3. else
    • for/else : break로 멈추지 않고, for 루프가 완전히 실행된 후에 else 블록이 실행된다
    • while/else : break로 멈추지 않고, 조건식이 거짓이 되어 while 루프를 빠져나온 후에 else 블록이 실행
    • try/else : try 블록에서 예외가 발생하지 않은 경우 else 블록 실행
  4. 순회 대상 생성
    • 수열 생성 : range([start,] stop[, step])

      • start 기본값 0. step 기본값 1. stop 자체는 미포함

    • 여러 시퀀스 동시 순회 : zip()

      • 같은 오프셋의 요소들로 튜플을 생성. 시퀀스가 하나라도 끝나면 순회 종료
      길이가 긴 시퀀스를 기준으로 하는 itertools.zip_longest()도 존재

    • comprehension : 순회를 통해 리스트, 딕셔너리, 셋 등 생성

      • 파이썬 3에서 comprehension은 함수처럼 고유한 지역 범위를 가진다

  5. Monkey patching

    6. 소스 코드를 건드리지 않고 런타임에 클래스나 모듈을 변경하는 행위

  1. 예외 그룹과 except* PEP 654

    2. ↓ python

    try: do() except* TypeError as eg: handle(eg.exceptions)
  2. 트레이스백이 ^^^^ 로 식 내부의 정확한 위치를 가리킨다 PEP 657
  3. e.add_note() 로 예외에 설명을 붙일 수 있다 PEP 678
  4. 성능이 3.10 대비 평균 1.25배 빨라졌다 (pyperformance 기준, 워크로드에 따라 10~60%)

Python 3.12

  1. 타입 파라미터 문법과 type 문 PEP 695

    2. ↓ python

    def max[T](args: Iterable[T]) -> T: ... class Stack[T]: ... type Alias[T] = list[T] | None
  2. f-string 문법이 정식 문법으로 편입됐다 PEP 701. 같은 따옴표 중첩, 백슬래시, 주석이 허용된다
  3. distutils 가 표준 라이브러리에서 제거됐다 PEP 632
  4. venv 가 setuptools 를 더 이상 선설치하지 않는다. 오래된 교재의 import setuptools, pkg_resources 가 그냥 실패한다. 필요하면 직접 설치한다

Python 3.13

  1. 타입 파라미터 기본값 PEP 696 — 이 릴리스의 유일한 문법 추가다

    2. ↓ python

    class Box[T = int]: ... type Foo[T, U = str] = Bar[T, U]
  2. 새 REPL 이 기본이 됐다 (위 절 참조)
  3. 컬러 트레이스백이 기본 활성화됐다. random.py 처럼 표준 라이브러리와 같은 이름의 스크립트를 만들었을 때 이름을 바꾸라고 알려준다 — 입문자가 가장 자주 겪는 실수다
  4. PEP 594 "dead batteries" 19개 모듈이 일괄 제거됐다

    5. ↓ text

    aifc audioop cgi cgitb chunk crypt imghdr mailcap msilib nis nntplib ossaudiodev pipes sndhdr spwd sunau telnetlib uu xdrlib

    2to3 도구와 lib2to3 도 함께 제거됐다

  5. free-threaded(GIL 없는) 빌드가 실험적으로 도입됐다

Python 3.14

  1. 템플릿 문자열 PEP 750 — f-string 과 달리 즉시 문자열이 되지 않고 Template 객체가 된다. SQL·HTML 처럼 안전한 조립이 필요한 곳에 쓴다

    2. ↓ python

    template = t'Try some {variety} cheese!' list(template) # ['Try some ', Interpolation('Stilton', 'variety', None, ''), ' cheese!']
  2. 괄호 없는 다중 except PEP 758 — as 절이 없을 때만 가능하다

    3. ↓ python

    try: connect() except TimeoutError, ConnectionRefusedError: retry()
  3. 어노테이션 지연 평가 PEP 649 — 어노테이션이 호출 시점까지 평가되지 않는다. 전방 참조를 문자열로 감쌀 필요가 없어졌다. 내성용으로 annotationlib 모듈이 추가됐다
  4. finally 블록을 빠져나가는 return / break / continue 에 SyntaxWarning 이 뜬다 PEP 765
  5. types.UnionType 이 typing.Union 의 별칭으로 통합됐다. int | str 과 Union[int, str] 이 같은 타입이 된다
  6. asyncio.get_event_loop() 이 실행 중인 루프가 없으면 RuntimeError 를 던진다. 암묵적으로 루프를 만들지 않는다
  7. Android 바이너리 릴리스가 제공되기 시작했다

free-threaded 와 JIT

  1. free-threaded(GIL 없는) 빌드 — 3.13 에서 실험적으로 도입돼 3.14 에서 PEP 779 로 공식 지원이 됐다
    • 다만 기본값이 아니다. 별도 빌드·실행 파일(python3.14t)을 써야 한다
    • 단일 스레드 성능이 약 5~10% 떨어지고 메모리는 15~20% 늘어난다
    • 확인 : sys._is_gil_enabled(). 런타임 강제 : PYTHON_GIL=1
    • C 확장은 free-threaded 전용 빌드가 필요하다
    • 기본 빌드로 만드는 단계는 아직 미정이며 별도 PEP 가 필요하다
  2. JIT 컴파일러 — 3.13 에서 PEP 744 로 도입됐고 3.14 에서도 여전히 실험적이다
    • python.org 의 공식 macOS · Windows 바이너리에 실험적 JIT 가 포함돼 있다. 토글은 PYTHON_JIT=0/1
    • 3.14 의 tail-call 인터프리터는 JIT 와 별개이며 소스 빌드 opt-in 이다
  3. 3.14.0~3.14.4 는 증분 GC 였으나 메모리 압박 보고로 3.14.5 에서 3.13 의 세대별 GC 로 되돌려졌다
