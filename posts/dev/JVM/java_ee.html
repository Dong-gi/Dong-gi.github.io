Java EE 에서 Jakarta EE 로

  1. 2017-09, Oracle 이 Java EE 를 Eclipse Foundation 으로 이관하겠다고 발표하고 EE4J 프로젝트가 개설됐다
  2. 2018-02, 커뮤니티 투표로 새 이름이 Jakarta EE 로 정해졌다 (약 7,000명 참여, 64.4%)
  3. 2019-05, Oracle 과의 협상이 결렬됐다. javax.* 네임스페이스를 Jakarta EE 커뮤니티가 진화시킬 수 없고, EJB·JPA·JAX-RS 처럼 "Java" 상표가 든 사양명도 쓸 수 없게 됐다
  4. 2020-12, Jakarta EE 9 에서 javax.* 를 jakarta.* 로 한 번에 전부 바꿨다. 점진적 이관 대신 big bang 을 택한 이유는, 리플렉션으로 패키지명을 참조하는 라이브러리들 때문에 중간 상태가 더 위험했기 때문이다
  5. 상표권 결정 원문

개발자가 체감하는 변화

Servlet 6.0 / 6.1

  • 6.0 에서 5.0 이전에 deprecated 였던 API 를 전부 제거했다. SingleThreadModel, HttpSessionContext, HttpUtils, HttpSession.getValue/putValue/removeValue 등
  • URI 디코딩·정규화가 엄격해졌다. 경로 탐색으로 보이는 시퀀스를 거부한다
  • 6.1 에서 HTTP/2 Server Push (newPushBuilder()) 가 deprecated 됐다. 103 Early Hints 로 대체를 권한다
  • 6.1 에서 SecurityManager 참조가 제거됐다 (JEP 411 대응)

Persistence 3.2

  • getSingleResultOrNull() 추가. NoResultException 을 catch 하지 않아도 된다
  • Java Record 를 @Embeddable / @IdClass 로 쓸 수 있다
  • java.time.Instant, java.time.Year 가 기본 타입으로 자동 매핑된다
  • @Temporal 과 java.util / java.sql 의 Date·Time·Timestamp·Calendar 가 deprecated 됐다. java.time 을 쓴다
  • @PersistenceContext 대신 CDI @Inject 로 EntityManager 주입이 가능하다
  • JPQL/Criteria 에 union, intersect, except, cast, || 등이 추가됐다
  • persistence.xml 없이 Java 코드로 퍼시스턴스 유닛을 구성할 수 있다

CDI 4.0 — 가장 파괴적인 변경

  • 빈 beans.xml 의 의미가 바뀌었다. 종전에는 explicit bean archive(discovery mode all)였으나 4.0 부터 implicit bean archive(annotated)로 취급한다
  • 즉 빈 정의 애너테이션이 없는 클래스는 더 이상 빈으로 등록되지 않는다. Java EE 8 앱을 올릴 때 "주입되던 것이 갑자기 안 된다"면 대개 이 문제다
  • CDI Full 제품은 구 동작으로 되돌리는 호환 스위치를 제공하게 되어 있다
  • 4.1 에서 프로듀서에 @Priority 를 지정할 수 있게 됐다

web.xml 스키마

Jakarta EE 9 이상은 모든 배포 서술자가 네임스페이스 하나를 공유하고 구분은 version 속성으로만 한다

↓ Jakarta Servlet 6.1 (EE 11 / Tomcat 11)

<?xml version="1.0" encoding="UTF-8"?> <web-app xmlns="https://jakarta.ee/xml/ns/jakartaee" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee https://jakarta.ee/xml/ns/jakartaee/web-app_6_1.xsd" version="6.1"> </web-app>

↓ 대조 — Java EE 8 / Servlet 4.0

<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://xmlns.jcp.org/xml/ns/javaee http://xmlns.jcp.org/xml/ns/javaee/web-app_4_0.xsd" version="4.0">

스키마 네임스페이스는 https 다. jakarta.ee 안내 페이지 본문에는 http 로 적힌 곳이 있으나 실제 XSD 의 targetNamespace 는 https 다

JSP 는 지금 어떤 위치인가

  • 사양은 유지되지만 유지보수 모드다. Jakarta EE 11 Web Profile 에 Pages 4.0 으로 들어 있고 Tomcat 11 도 구현하지만, 사양의 방침은 "예기치 못한 문제 수정과 Servlet·EL 변경에 맞춘 적응"이며 새 기능 개발은 없다
  • Jakarta Faces 4.0(EE 10)에서 JSP 가 뷰 기술로서 완전히 제거됐다. Faces 의 뷰 선언 언어는 이제 Facelets 하나뿐이다
  • 신규 개발에는 권장되지 않는다. 서버 사이드 렌더링이 필요하면 Faces + Facelets, 아니면 Core Profile(REST + JSON-B) + 프런트엔드 프레임워크 조합을 쓴다

  3. urlPatterns : 배포설명자의 url-pattern들의 배열에 해당
  4. value : urlPatterns 요소와 동일하게 동작하기 때문에, 서블릿 매핑만을 기술할 거라면 편하게 WebServlet("/hello")처럼 기술할 수 있다

    6. GenericServlet#getInitParameter로 참조할 수 있으며, 이 메서드는 ServletConfig#getInitParameter를 호출한다. ServletConfig는 GenericServlet#getServletConfig 메서드로 참조할 수 있다

  6. loadOnStartup : 컨테이너가 애플리케이션을 시작할 때, 클라이언트의 요청이 없어도 미리 해당 서블릿을 인스턴스화 한다

서블릿

다른 페이지로 이동/호출

  1. 다른 페이지로 이동
    • Refresh : 응답 페이지를 보여준 뒤 클라이언트가 나중에 다시 요청하도록 한다
    • Redirect : 응답 페이지 없이 바로 다른 url을 요청하도록 한다

      • 따라서 redirect의 경우에는 getWriter()를 이용하지 말아야 한다

  2. 다른 페이지 호출
    • Forward
      • 호출하는 페이지로 제어를 넘기기 때문에 해당 페이지가 종료되도 제어가 되돌아오지 않는다

        • 따라서 forward를 호출하는 측은 getWriter()를 이용하지 말아야 한다 + 호출자 자신과 동일한 페이지/서블릿을 호출할 수 있다

      • forward는 서버 내에서 요청/응답 객체를 넘겨주므로 별도의 인코딩 없이 텍스트나 다른 객체를 추가하여 넘겨줄 수 있다
    • Include
      • Forward와 달리 호출된 페이지가 종료되면 제어가 돌아온다

JSP

  1. JSP 파일은 클라이언트 요청으로 필요해지면 HttpJspPage 인터페이스를 구현한 서블릿 클래스로 컴파일되고, 해당 서블릿이 요청을 처리한다
  2. JSP 파일의 본문은 HttpJspPage#_jspService 메서드의 본문이 된다
  3. HttpJspPage → JspPage → Servlet

    4. JspPage 인터페이스는 jspInit(), jspDestroy()를 정의한다

  4. JSP 태그
    • <%@ %> : 지시자; Directive : page, taglib, include 3종류가 있다
    • <% %> : Scriptlet : 일반 자바 코드를 작성하면 된다. _jspService 메서드 안의 코드로, 매개변수를 포함한 아래의 변수들을 참조할 수 있다
    • <%! %> : 선언문; Declaration : 서블릿 클래스의 멤버 정의
    • <%= %> : Expression : out#print 또는 out#write에 들어갈 값을 반환하는 문장을 작성하면 된다

    initParams : 서블릿 초기화 매개변수. 서블릿 내에서 GenericServlet#getInitParameter로 참조할 수 있다

  4. HttpSession

  5. ServletRequest

    6. (클라이언트 요청 처리) 스레드 수준 공유 데이터. 서블릿마다 자동으로 공유되지는 않으며, 직접 전달해야 한다

  6. 각 클라이언트의 요청이 별개의 스레드에서 실행되므로, ThreadLocal이 유용할 수 있다
  7. JspContext

    8. _jspService()에서 자동 선언하는 pageContext 지역변수(). JSP 실행하는 동안 유효

javax.servlet 이벤트 리스너

이벤트 리스너 구현 클래스는 배포 설명자에 서술되거나, @WebListener를 표기하거나, ServletContext#addListener로 등록돼야 한다

  • @WebListener 표기 가능 리스너 : ServletContextListener, ServletContextAttributeListener, ServletRequestListener, ServletRequestAttributeListener, HttpSessionListener, HttpSessionAttributeListener, HttpSessionIdListener
  • ServletContext#addListener 등록 가능 리스너 : ServletContextAttributeListener, ServletRequestListener, ServletRequestAttributeListener, HttpSessionAttributeListener, HttpSessionIdListener, HttpSessionListene

    • ServletContext 인스턴스가 ServletContainerInitializer#onStartup()으로 설정됐다면 ServletContextListener도 등록 가능

    6. built-in 별명 : _int(int), int(java.lang.Integer), date(java.util.Date) 등

    • environment » transactionManager » type 속성 : JDBC(MyBatis에서 트랜잭션 관리), MANAGED(서버나 서블릿 컨테이너에서 트랜잭션 관리)

      • ↓ POOLED

      ↓ JNDI

      <dataSource type="JNDI"> <property name="data_source" value="jdbc/MySQL/localhost/test"/> </dataSource>
